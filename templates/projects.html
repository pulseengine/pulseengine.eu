Architect — spar

A compiler for system-architecture models: it ingests AADL v2.3, SysML v2, and CAN/DBC into one semantic model, then runs pluggable analysis passes — safety analysis, ARINC 653 partitioning, and TSN timing bounds — plus a deployment solver, code generation (WIT, Rust, Lean 4 proofs, rivet docs, Bazel), SVG rendering, and an LSP server. Compiles to a single WebAssembly component.

spar is architecturally upstream — it validates system design before any code exists, then generates the interfaces and skeletons that feed into the build pipeline.

Build — the pipeline

meld fuses multiple WebAssembly components into a single module. loom runs multi-pass optimization via Cranelift ISLE. synth transcodes to native ARM (Cortex-M, Cortex-R5, AArch64/ARMv8) and RISC-V. sigil signs and attests transformations with Sigstore or Ed25519; it began as a takeover of Frank Denis's wasmsign2 (MIT), since heavily diverged.

Four separate tools, one flow. Every stage is independently verifiable.

Verify — deductive proof, abstract interpretation, and empirical coverage

Verus checks requires/ensures contracts on Rust source via SMT/Z3; functions marked external_body are trusted, not checked. Rocq machine-checks invariants; in gale and relay these are hand-written abstract models, not connected to the Rust. Lean 4 proves results about models of the domain: in gale, rate-monotonic utilization bounds, the priority ceiling protocol and ring-buffer index arithmetic. All three work pre-compilation, on the source or on models of it. scry adds the third DO-333 formal-methods technique — sound abstract interpretation over the fused Wasm Core module, computing invariants that hold for all executions and feeding them downstream to loom and sigil-signed evidence to rivet. witness then measures MC/DC structural coverage on the resulting post-compilation Wasm — the empirical half that closes the §FM.6.7(f) / structural-coverage cell DO-178C, ISO 26262 Part 6 Table 12, and IEC 61508 Annex C expect. Together they form an evidence chain no single technique spans: proof and abstract interpretation cover all inputs in principle; witness measures what actually ships in the wasm bytecode. witness v0.14+ emits v3 MC/DC envelopes with DWARF inline-chain tracking up to 8 levels deep on real Rust (httparse).

How far each technique reaches differs by project. gale and relay run Verus, Kani, Rocq and Lean in CI on specific properties, and gale's and relay's docs say what is proven, what is bounded and what is only tested. A green proof job is not the same as everything proven: Rocq accepts Admitted, and Verus trusts external_body. ordeal underwrites the deductive layer itself — a pure-Rust, wasm-native QF_BV SMT solver whose untrusted core is paired with a formally-verified LRAT proof checker (the CompCert pattern), so even the solver's own answers carry evidence a checker can re-verify.

Trace — rivet

Schema-driven SDLC artifact manager with two dozen-plus built-in schemas covering ISO 26262, ISO/PAS 8800, ASPICE, DO-178C, IEC 61508, IEC 62304, EN 50128, EU AI Act, SOTIF, STPA, STPA-Sec, STPA-AI, GSN safety cases, AADL import, Eclipse SCORE, V&V coverage, cybersecurity, supply chain, and more — plus cross-domain bridge schemas. Validates on every commit — broken links fail the build.

Imports AADL models from spar and test results from CI. Compliance reports generate on every release. LSP server, MCP server, dashboard.

Run — platforms & applications

kiln is a WebAssembly Component Model runtime with a WASI 0.2 and no_std architecture for embedded targets — in active early development. gale's North Star is gust — a general, multi-tenant verified OS composed from verified parts, MPU-isolated over a tiny Rust trusted base. It began as a Rust replacement for Zephyr RTOS kernel primitives (39 modules) and still provides those — machine-checked across Verus, Rocq, and Lean, ASIL-D targeted, with an honest claims ledger (some proofs are over abstract models; parts of the scheduler are still admitted stubs). The same components run live in your browser and dissolve to a bare-metal (emulated) Cortex-M3.

Built on top: relay — flight-software components for WebAssembly, inspired by NASA's cFS, with formal proofs of specific safety properties: Verus contracts on the cFS mission-layer crates, Kani bounded model checking of their engines, and Lean for the attitude controller's Lyapunov algebra. wohl is safety-critical home supervision. Both are applications where the methodology has to hold up in a real domain.

Agent — AI-native development

rivet mcp exposes a full tool suite to AI agents — validate, add artifacts, link, check coverage, stamp provenance. Agents write code AND maintain traceability as part of their workflow.

rivet stamp records AI session provenance. mcp is the Rust framework for building MCP servers. spar wasm runs architecture analysis in-browser at 1.3 MB. Agents coordinate through GitHub issues and releases, which are durable, signed and auditable without new infrastructure to trust.

Built on the base

The six faces above are the toolchain. These are products made with it — each one drives the same loop end to end, and each is where the methodology has to survive contact with a real domain.

relay
flight software

Flight-software components for WebAssembly, inspired by NASA's cFS and reimagined as generic components. Formal proofs of specific safety properties: Verus contracts on the mission-layer crates, Kani bounded model checking, Lean for the controller's Lyapunov algebra.

wohl
home supervision

A wireless field-sensor product on STM32G0 — CCSDS payloads over a sub-GHz radio, bridged at the hub. The small-target end of the range, where footprint decides what is possible.

jess
hardware integration

Where software meets hardware: carries relay's falcon flight stack from simulation through hardware-in-the-loop to a real drone, tracked in rivet the whole way.

Beneath all of it, varve delivers the toolchain itself — the exact binaries a build ran, as one signed, dated, digest-pinned layer. It is not a stage in the pipeline; it is what makes “which pipeline” answerable.
